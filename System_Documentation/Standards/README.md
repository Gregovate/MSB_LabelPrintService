# MSB Documentation Standards

These standards define how documentation is written and maintained across the MSB Production Database Project. The working-contract and prompt standards are intentionally reusable for other version-controlled engineering projects Greg and ChatGPT work on together.

## Start Here

Start with [Documentation Standards](Documentation_Standards.md) for the project-wide principles. Use the more specific standards below when creating, revising, or resuming work.

## What Do You Need To Do?

| I want to... | Go to |
|---|---|
| Understand the overall documentation rules | [Documentation Standards](Documentation_Standards.md) |
| Preserve reverse-engineering discoveries and other durable system knowledge during engineering work | [Documentation Maintenance Rule](Documentation_Maintenance_Rule.md) |
| Decide what belongs in the core repository versus a dedicated subsystem/application repository | [System Boundary and Repository Ownership Standard](System_Boundary_and_Repository_Ownership_Standard.md) |
| Create or revise a README portal or engineering handoff | [README Portal Standard](README_Portal_Standard.md) |
| Create or revise an operator procedure / SOP | [Operational SOP Standard](Operational_SOP_Standard.md) |
| Add document control or revision history | [Document Control Standard](Document_Control_Standard.md) |
| Create or repair navigation and links | [Linking and Navigation Standard](Linking_and_Navigation_Standard.md) |
| Format Markdown consistently | [Markdown Style Guide](Markdown_Style_Guide.md) |
| Start or resume a project with the reusable Greg/ChatGPT working contract | [Prompt Guidelines](Prompt_Guidelines.md) |

These documents are the source of truth for documentation behavior. Subsystem documents should follow them rather than inventing their own competing standards.

For active engineering subsystems, the responsible README is also the current development handoff. Material work is not complete until that README has been reviewed and updated when necessary so the next session can resume from the repository rather than reconstructing settled decisions from conversation history.
